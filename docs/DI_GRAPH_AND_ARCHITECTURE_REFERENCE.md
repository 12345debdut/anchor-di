# Anchor DI — Graph Building, Data Structures & Architecture Reference

> Quick reference for answering project questions about how the DI graph is built, what data structures are used, and key architecture decisions.

---

## 1. Library Module Structure

| Module | Purpose |
|--------|---------|
| **anchor-di-api** | Annotations & public API (`@Inject`, `@Module`, `@Provides`, `@Binds`, `@Component`, etc.) |
| **anchor-di-core** | Runtime container, `Key`, `Binding`, `Factory`, `AnchorContainer`, `Anchor` |
| **anchor-di-ksp** | KSP processor: model building, validation, code generation |
| **anchor-di-compose** | Compose Multiplatform: `anchorInject()`, `viewModelAnchor()`, `NavigationScopedContent` |
| **anchor-di-presentation** | `NavigationScopeRegistry`, `ViewModelScopeRegistry` |
| **anchor-di-android** | `ActivityScope` (Android-specific) |

## 2. Core Data Structures (Runtime)

### 2.1 Key
```kotlin
data class Key(val typeName: String, val qualifier: String? = null)
```
- **Purpose:** Uniquely identifies a binding in the container.
- **typeName:** Fully-qualified class name (e.g. `com.example.Repository`).
- **qualifier:** Optional, from `@Named("...")` or custom qualifiers.
- **Special keys:** `Set<T>` → `kotlin.collections.Set<elementFqn>`, `Map<String,V>` → `kotlin.collections.Map<kotlin.String,valueFqn>`.

### 2.2 Binding (sealed class)
| Variant | Use Case |
|---------|----------|
| `Binding.Unscoped(factory)` | New instance per request |
| `Binding.Singleton(factory)` | One instance per root container |
| `Binding.Scoped(scopeClassName, factory)` | One instance per scope (ViewModel, Navigation, custom) |
| `Binding.MultibindingSet(List<Factory>)` | `@IntoSet` contributions merged into a Set |
| `Binding.MultibindingMap(List<Pair<Any,Factory>>)` | `@IntoMap` with `@StringKey` contributions |

### 2.3 Factory
```kotlin
interface Factory<out T : Any> {
    fun create(container: AnchorContainer): T
}
```
- **Purpose:** Creates instances; receives container to resolve dependencies.
- **Source:** Generated by KSP from `@Inject` constructors and `@Provides` / `@Binds` methods.

### 2.4 BindingRegistry
```kotlin
interface BindingRegistry {
    fun register(key: Key, binding: Binding)
    fun registerSetContribution(key: Key, factory: Factory<Any>)
    fun registerMapContribution(key: Key, mapKey: Any, factory: Factory<Any>)
}
```
- Used during `contribute()` to register bindings into the container.
- Implemented by an internal object inside `AnchorContainer.buildBindings()`.

### 2.5 ComponentBindingContributor
```kotlin
interface ComponentBindingContributor {
    fun contribute(registry: BindingRegistry)
}
```
- **Purpose:** Generated objects that register all bindings for a component/module.
- App passes `AnchorGenerated` (or multiple contributors) to `Anchor.init()`.

## 3. AnchorContainer — The DI Graph at Runtime

### 3.1 Construction
```kotlin
class AnchorContainer(
    contributors: List<ComponentBindingContributor>,
    parent: AnchorContainer? = null,
    currentScopeId: String? = null,
    inheritedBindings: Map<Key, Binding>? = null
)
```

### 3.2 Internal Data Structures
| Field | Type | Purpose |
|-------|------|---------|
| `bindings` | `Map<Key, Binding>` | Immutable map of all bindings (safe for concurrent reads) |
| `singletonCache` | `MutableMap<Key, Any>` | Cached singleton instances (at root only) |
| `scopedCache` | `MutableMap<Key, Any>` | Cached scoped instances per scope |
| `cacheLock` | `SyncLock` | Single lock for all caches (prevents deadlocks) |
| `parent` | `AnchorContainer?` | Parent container for child scopes |

### 3.3 How `buildBindings()` Works
1. Create mutable maps: `mutableBindings`, `setContributions`, `mapContributions`.
2. Create a `BindingRegistry` implementation that:
   - `register` → `mutableBindings[key] = binding`
   - `registerSetContribution` → append to `setContributions[key]`
   - `registerMapContribution` → append to `mapContributions[key]`
3. Call `contributors.forEach { it.contribute(registry) }`.
4. Merge set contributions → `Binding.MultibindingSet`.
5. Merge map contributions → `Binding.MultibindingMap`.
6. Return `mutableBindings.toMap()` (immutable).

### 3.4 Resolution Flow (`get(key)`)
1. Look up `bindings[key]`; throw if missing.
2. Switch on binding type:
   - **Unscoped:** `factory.create(resolveContainer(binding))` — new instance.
   - **Singleton:** Resolve from **root** container's `singletonCache` (walk up parent chain).
   - **Scoped:** If `currentScopeId == binding.scopeClassName` → resolve from `scopedCache`; else delegate to parent.
   - **MultibindingSet/Map:** Resolve from root `singletonCache`, creating Set/Map from contributions.

### 3.5 Scope Hierarchy (Parent–Child)
- **createScopeContainer(scopeClass) / createScopeContainer(scopeId):** Creates child container with:
  - `contributors = emptyList()`
  - `parent = this`
  - `currentScopeId = scopeClass.qualifiedName` or `scopeId`
  - `inheritedBindings = bindings` (reuses parent bindings, no re-registration)

## 4. KSP Pipeline — How the Graph is Built at Compile Time

### 4.1 Phases in AnchorSymbolProcessor
1. **Discovery:** Collect `@Inject` classes and `@Module` classes via `resolver.getSymbolsWithAnnotation()`.
2. **Model build:** `AnchorDiModelBuilder` builds:
   - `components` — `Map<String, ComponentDescriptor>`
   - `bindings` — `List<BindingDescriptor>`
   - `injectClassDescriptors`, `moduleDescriptors`
   - `(providedKeys, requirements)` — what’s provided vs required
   - `dependencyGraph` — `Map<String, Set<String>>` (node → dependencies)
3. **Validation:** `AnchorDiValidator` runs symbol passes then model passes.
4. **Codegen:** `AnchorDiCodeGenerator` emits factory classes and contributor objects.

### 4.2 AnchorDiModel (KSP-side descriptors)
| Descriptor | Purpose |
|------------|---------|
| `ComponentDescriptor(fqn, dependencies)` | Component metadata |
| `BindingDescriptor(key, qualifier, component, scope, source, multibindingKind?, mapKey?)` | Single binding |
| `ModuleDescriptor(moduleName, installInComponentFqn, hasProvidesOrBinds, bindsMethods)` | Module metadata |
| `BindsMethodDescriptor(moduleName, methodName, parameterCount)` | `@Binds` method |
| `DependencyRequirement(requiredType, requester)` | Dependency edge for validation |

### 4.3 Dependency Graph
```kotlin
Map<String, Set<String>>  // node FQN -> set of dependency FQNs
```
- Built from `@Inject` constructor parameters and `@Provides` / `@Binds` method parameters.
- `Lazy<T>` and `AnchorProvider<T>` are unwrapped to inner type and not added as edges (break cycles).
- Used for cycle detection and reachability validation.

### 4.4 Component Resolution
- Components discovered via `@Component` annotation (no hardcoded list).
- `ComponentResolution.discoverComponentFqns()` / `discoverComponentDescriptors()`.
- Built-ins: `SingletonComponent`, `ViewModelComponent`, `NavigationComponent` (from ValidationConstants).

## 5. Scope Hierarchy (Validation & Runtime)

### 5.1 Built-in Components
| Component | Scope FQN | Parent | Longevity |
|-----------|-----------|--------|-----------|
| SingletonComponent | `com.debdut.anchordi.SingletonComponent` | — | 2 (longest) |
| ViewModelComponent | `com.debdut.anchordi.ViewModelComponent` | Singleton | 1 |
| NavigationComponent | `com.debdut.anchordi.NavigationComponent` | ViewModel | 0 (shortest) |

### 5.2 Scope Lifetime Rules
- Longer-lived scopes cannot depend on shorter-lived (e.g. Singleton cannot depend on ViewModel-scoped).
- `ScopeHierarchy.longevityRank()`, `parentOf()`, `scopeAllowedInComponent()` enforce this.

## 6. Validation Pipeline

### 6.1 Symbol Phase (per symbol)
- `MultipleInjectConstructor` — only one `@Inject` constructor
- `InjectableClassKind` — class kind checks
- `ConstructorAccessibility` — constructor visibility
- `BindsImplementation` — `@Binds` param is `@Inject` class
- `SingleScope` — at most one scope annotation

### 6.2 Model Phase (on model context)
- `ModuleInstallIn` — modules have valid `@InstallIn`
- `ModuleBinds` — `@Binds` method structure
- `AnchorViewModel` — `@AnchorViewModel` requirements
- `DuplicateBinding` — no duplicate (key, qualifier, component)
- `UniqueScopeInHierarchy` — scope uniqueness in component tree
- `ScopeComponentCompatibility` — scope matches component
- `ScopeLifetimeViolation` — no longer-lived depending on shorter-lived
- `MissingBinding` — all requirements have providers
- `Cycle` — no cycles (DFS; suggests `Lazy<T>` or `AnchorProvider<T>` to break)
- `ReachableBindings` — all bindings reachable from entry points

## 7. Generated Code Shape

### 7.1 File Layout (multi-module)
- `AnchorGenerated_<moduleId>_<ModuleName>_Factories.kt` — factories for `@Inject` classes in that module
- `AnchorGenerated_<moduleId>_<ModuleName>.kt` — contributor for that module
- `AnchorGenerated_<moduleId>_Inject_Factories.kt` — factories for non-module-bound `@Inject` classes
- `AnchorGenerated_<moduleId>_Inject.kt` — contributor for those
- `AnchorGenerated_<moduleId>.kt` — aggregator that delegates to all contributors

### 7.2 Grouping Logic
- `@Inject` classes: grouped by module that `@Binds` them (if exactly one); else `"Inject"`.
- `@Provides` / `@Binds`: grouped by `@Module` simple name.
- `implFqnToComponent` / `implFqnToModule` from `buildBindsImplComponentMap` / `getBindsImplModuleMap`.

### 7.3 Factory Generation
- For `@Inject` class: generate `ClassName_Factory : Factory<ClassName>` that:
  - Resolves each constructor param via `container.get<T>()`, `container.get<T>(qualifier)`, `lazy { }`, or `AnchorProvider<T>`.
  - Returns `ClassName(param1, param2, ...)`.

## 8. Entry Points & Initialization

### 8.1 Anchor (singleton)
- `Anchor.init(vararg contributors)` — creates `AnchorContainer(contributors)`.
- `Anchor.inject<T>()`, `Anchor.inject<T>(qualifier)` — resolve from container.
- `Anchor.withScope(scopeClass) { block }` — run block in scoped container.
- `Anchor.scopedContainer(scopeClass)` — create scoped container for manual use.
- `Anchor.reset()` — clears container; invokes reset listeners (e.g. `NavigationScopeRegistry.clear()`).

### 8.2 NavigationScopeRegistry
- `getOrCreate(scopeKey)` → `NavigationScopeEntry(navContainer, viewModelContainer)`.
- Both containers are children of root: `Anchor.scopedContainer(NavigationComponent.SCOPE_ID)` and `ViewModelComponent.SCOPE_ID`.
- `dispose(scopeKey)` — removes entry, calls `clear()` on both containers.
- Cleared when `Anchor.reset()` is called.

### 8.3 ViewModelScopeRegistry
- Delegates to `NavigationScopeRegistry.getOrCreate(scopeKey).viewModelContainer`.
- Same lifecycle as navigation scope for that key.

---

## 9. Thread Safety

- `bindings`: immutable after build; safe for concurrent reads.
- `singletonCache`, `scopedCache`: protected by single `cacheLock` (avoids deadlocks from cross-scope deps).
- `Anchor.init` / `Anchor.reset`: use `lock`; `addResetListener` is thread-safe.
- `NavigationScopeRegistry`: uses `SyncLock` for `entries` access.

---

## 10. Special Types Handled by KSP

- **Lazy&lt;T&gt;:** Unwrapped to `T` for dependency graph; factory generates `lazy { container.get<T>() }`.
- **AnchorProvider&lt;T&gt;:** Unwrapped to `T`; factory generates provider that delegates to `container.get<T>()`.
- **Skipped in graph:** `kotlin.Lazy`, `AnchorProvider`, `kotlin.String`, `kotlin.Int`, etc. (ValidationConstants.SKIPPED_TYPES).

## 11. Quick Answer Cheat Sheet

| Question | Answer |
|----------|--------|
| Primary data structure for bindings? | `Map<Key, Binding>` in `AnchorContainer` |
| How is the graph built? | KSP discovers symbols → `AnchorDiModelBuilder` builds descriptors + dependency graph → validators run → `AnchorDiCodeGenerator` emits factories + contributors |
| How does scope resolution work? | `currentScopeId` on container; scoped bindings resolve from `scopedCache` if scope matches, else delegate to parent |
| Where are singletons cached? | Root container's `singletonCache`; resolution walks up to root |
| How to break cycles? | Use `Lazy<T>` or `AnchorProvider<T>` for one dependency |
| Multi-module setup? | `anchorDiModuleId` KSP arg per module → `AnchorGenerated_<id>`; combine contributors in app `getAnchorContributors()` |
| Test support? | `Anchor.reset()` then `Anchor.init(TestContributor)`; contributors override by registration order |
